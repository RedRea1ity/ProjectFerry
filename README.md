> 人无语言则茫然无依，故为摆渡。
> Where words fail, we ferry。

> **开发中 · v1.9.0-beta（预发布）**

> 聊天栏路径刚从 Mixin 改成 Forge 官方事件 `ClientChatReceivedEvent`，**还没实机验证** ——

一个 Minecraft 模组 AI 汉化工具。。。我不懂编程，这算是靠 AI 一点点许愿许愿出来的、第一个敢往 GitHub 上放的东西（大概）（不过放完就后悔了）（这句话是真的）。

它干的事其实挺简单：进你的整合包，看看哪些模组没中文，然后用 AI 把缺的那部分补上。。**只补缺口，绝不动你已经有的人工/官方汉化**——一旦检测到别人翻过了，它就自己/run（渡你过河，到岸即离）。所有改动都写在资源包里，删掉就恢复原样，模组本体一根毛都不碰。。至于那句文绉绉的slogan，其实灵感来自《边狱巴士》零协汉化组那句「人无语言则茫然无依」，听着有点傻逼，但我大概是认真的，吧。？

- 自带检测到人工汉化自动退位（自我削除谢谢喵）。孩子们这就是我们全世界最尊重汉化组的临时ai汉化工具的嘴脸。（目前只有资源包汉化）

## 怎么打开

- 不想装 Python，去 [Releases](https://github.com/RedRea1ity/ProjectFerry/releases) 下 `ProjectFerry.exe`，免安装。这个 exe 是 CI 打 tag 时自动构建的（仓库里**不再放**这个 13 MB 的二进制 —— 放一份就跟源码不同步了，容易让人以为那就是最新版），我自己打包那次差点把图标搞丢哈哈。。。
- 装了 Python 就双击 `ProjectFerry.bat`，不会有黑框闪一下就没了这种事，我测过呃。
- 或者双击 `ProjectFerry.pyw`，前提是系统关联了 Python。

打开之后它自己去本机找 MC 实例填进上面的下拉框。选一个，下面列表就是缺中文的模组。找不到实例多半是启动器目录太歪了，点「浏览」手动指路吧。。。

## 它能做啥、不能做啥

能做的是扫描模组语言文件，老的 `.lang` 也认，找出没中文的 key，用翻译引擎生成一个低优先级的资源包，默认引擎是免费的 MyMemory。有人工汉化就自动让位，这条是刻在代码里的，不是嘴上说说呃。

不能直接做、绕路做了的，是写死在模组代码里的文字，还有存在物品 NBT 里的描述。这些压根不在语言文件里，资源包永远盖不住，我做到一半才发现这个坑哈哈，那会儿人都是麻的。摆渡的办法是配合一个显示层替换的模组，把「英文原文 → 中文」的规则丢给它，让它在游戏里替换显示，见下面「桥接」那章。存档照样一个字节不动，这个也不敢动。

真做不了的是烤在图片和纹理里的字。这个谁都没辙，除非把美术也 AI 了（别）。

每次扫完，底部「汉化限制」按钮会列出疑似含硬编码文本的模组，是启发式检测，就是翻 `.class` 里的字符串常量，会混进一些奇奇怪怪的东西，仅供参考。我第一次跑的时候它把一条报错日志也当 UI 文本报上来了哈哈，尬。

## 桥接：NBT 和硬编码的显示层替换

先说下为什么会硬编码呃，有些作者把物品备注、任务文本直接写死在代码里，不走语言文件，资源包拿它毫无办法。可文字最后总要渲染到屏幕上，那就在渲染层替换呗。我头铁要自己写一个模组把所有版本适配了，写着写着发现天真了，拆开社区里 LiteralBridge 的 jar，看见人家连 mixin 都铺好了，遂跪哈哈，原地改成给人家供数据（这个格式的对接来回改过好几次，翻车记录都在更新日志里，不展开了）。

1. 扫描加翻译完，点底部「**导出桥接映射**」，它写两样东西：
   - `<实例>/config/literalbridge/ferry.json`，英文原文 → 翻译键的规则文件，LiteralBridge 的标准外部格式，改完自动热重载，游戏都不用重启呃；
   - 资源包里补 `assets/literalbridge/lang/zh_cn.json`，翻译键 → 中文。
2. 确认实例 `mods` 里有 [LiteralBridge](https://github.com/Losketch/LiteralBridge)。没有的话**导出时会自动从 GitHub 下载**匹配你加载器和游戏版本的那个 jar，直接丢进 `mods`（模组要重启游戏才加载）；只有网络不通、或没有支持你这个「加载器 + 版本」的本体时，才回落成打开项目页让你自己下呃。已经装了的实例，勾着「自动升级 LiteralBridge」时还会顺带查一次新版，有就换掉（旧版改名成 `.jar.bak-…` 留在原地备份）。
3. 进游戏，硬编码文本在显示层变成中文。删掉模组和规则文件就回原样，跑路成本为零。

硬编码文本的翻译，设置摘要行勾上「**翻译硬编码文本**」后，检测器扫出来的疑似硬编码英文会随翻译批一起交给 AI，译文存资源包旁的 `.hardcoded.json`，导出时一并并进规则。检测是启发式的，会混进一些奇怪的句子，翻出来偶尔有废话，别惊讶，反正精确匹配，游戏里没这句就永远不显示，顶多浪费我一点 token 和你一点 AI 额度呃。（命令串比如 `/execute`、`@e[…]` 会被自动剔掉，不会再混进来浪费额度。）

感谢 [Losketch](https://github.com/Losketch) 的 LiteralBridge，我本来要自己造的轮子，人家早造好了还带热重载哈哈。他出钩子，我出数据，你出整合包，多么完美的分工（他就是不知道而已，我还没好意思去他仓库留言呃）。

自研的摆渡桥模组在 `bridge/` 目录里，作为 LiteralBridge 没覆盖到的版本和加载器的兜底 —— **已经解冻并在做**，不是废弃呃，万一哪天 LiteralBridge 弃坑了还得靠它顶。规模化路线（大批量翻译 / 多加载器 / 多版本）见 [docs/PLAN_SCALE_UP.md](docs/PLAN_SCALE_UP.md)。

需要说明的是：LiteralBridge 官方 Release 目前**只有 Forge 版，MC 版本范围 `[1.20.1, 1.21)`**（它自己 mods.toml 里写的）。所以在 NeoForge、以及 1.21 以上的版本上，硬编码汉化得靠摆渡自研桥来兜 —— 摆渡不会往那种实例里硬塞一个装不上的 Forge 版 jar，会老实告诉你「没有匹配的本体」。

### 大批量翻译怎么用（桌面一条龙，不用进游戏）

桥自己不会翻译，它的映射表得有人往里填。**推荐全程在摆渡里做完**：

**主流程 · 桌面静态扫描** —— 不用进游戏：

1. 勾上设置摘要行的「**翻译硬编码文本**」，选中要处理的模组，正常点「开始翻译」。
   摆渡会直接扒这些 jar 的 `.class` 常量池，把**写死在代码里**的英文（物品 tooltip、
   Shift 展开的详细说明、聊天台词……）一次全抓出来交给 AI，译文存进资源包旁的
   `.hardcoded.json`。
2. 翻译收尾时会**自动**把当前所有已知映射（语言文件译文 + 硬编码译文）写进游戏目录的
   `ferrybridge-mappings.json`（想手动也行，点底部「**导出桥接映射**」）。
3. 进游戏就是中文了。之后每次改完重新翻译 / 导出即可，**游戏不用重启**。

**开发者补漏 · 游戏内采集** —— 只用来兜底静态扫描抓不到的：

动态拼接出来的文本、被启发式误判漏掉的句子，会在游戏里被桥记下来：

1. 进游戏正常玩一圈（悬停物品、看聊天栏）。桥会把**出现过、但映射表里没有译文**的
   英文，按「聊天栏 / 物品 tooltip」分桶记到游戏目录的 `ferrybridge-collected.txt`。
   按 **F9** 能实时看到「已采集 N 条」在涨。
2. 回摆渡，点底部「**导入游戏采集（开发者补漏）**」，读那份清单、批量翻译，写进同一份映射表。
3. 游戏里**不用重启**，按 F9 能看到「已替换」开始涨。

两个入口写的是**同一个文件**，摆渡会**合并**：导出的批次除了自己那批，原有的条目照样留着
（先前的 bug 是两边都整表覆盖，谁后点谁赢，会把先点的全抹掉，已修）。

命令行等价物：`python mc_ai_translator.py bridge-collect --instance <实例目录>`。

采集器只记录、不翻译，也永远不会自动替换——玩家自己敲进聊天框的话虽然会被记下来，
但它不在表里就一直是原文。这条由「整条精确匹配」那条红线保证。

**日常排查用自检模式**，游戏保证能启动、不做任何替换：

- 临时：启动参数加 `-Dferrybridge.safe=true`
- 长期：在游戏目录建 `ferrybridge.json`，内容 `{"enabled": false}`

无论开关如何，桥都会在游戏目录生成 `ferrybridge-diagnostic.txt`，
用人话写清「映射多少条 / 几个注入点活着 / 坏了该修什么」，
不用再去翻 `latest.log` 猜 Java 堆栈。

## 默认会过滤掉的模组

纯前置、库、性能优化、底层修复类的模组默认不翻，比如 Architectury、Cloth Config、GeckoLib、KuroLib、内存泄漏修复、星光、FerriteCore、Entity Culling、ModernFix 之类。翻这些纯属烧钱，翻完了玩家也看不见呃。

地图、JEI、Jade、背包整理、枪械、任务、怪物这些面向玩家的都不过滤。被过滤的模组还是老老实实待在游戏里，只是不进「待汉化」列表。要是你觉得哪个被过滤的其实该翻，GUI 点「用户白名单」把 modid 加进去，保存后重扫就行，白名单存在 `ferry_whitelist.json`，下次打开还在。

## 人工汉化优先（这条是底线，也是全部卖点）

扫描时把中文来源分成几类，模组自带和社区包里的 `zh_cn` 算人工汉化；本工具上次生成的 AI 包靠包里的 `AI_TRANSLATION_NOTICE.txt` 认出来，不算呃。

规则就一条，只要某模组有人工汉化，哪怕只翻了一半，默认就不给它生成 AI 翻译，保持原样，没人翻的才进「待 AI 翻译」。这条没什么好商量的，别人熬夜翻的字被 AI 盖掉这种事我做不出来。

而且它会自己撤场，如果汉化组在你用完之后又补上了译文，下次扫描摆渡会主动把之前自己生成的那几条从资源包里删掉，删到整个包都空了就把包文件一并删掉。不是「不覆盖」，是「擦掉自己的」。每次撤场都会在状态栏播报，并在包内 `AI_TRANSLATION_NOTICE.txt` 留一条带时间戳的记录：

```
摆渡退场记录（这些都是摆渡主动撤回的，不是翻译失败）：
  · [2026-10-08 16:52] 撤回自己此前生成的 4 条译文（tacz）
  · [2026-10-08 17:03] 撤回自己此前生成的 2 条译文（jei）
```

AI 汉化只是临时顶替用呃，真正的汉化还是在于人对模组故事剧情的理解，所以我让它到岸即离。

几个可选玩法：

- `--fill-community`，只补「有人工汉化但不完整」的模组缺的那几个 key，不改已有译文。
- GUI 勾「参考人工汉化语料补全缺失 key」或 `--refine-community`，把同一个模组现有的 `en_us` 和人工 `zh_cn` 配对当术语和文风参考，只让 AI 翻人工和现有 AI 包都没覆盖的 key。已有人工译文永远不会被当待翻译项，也不会写进 AI 包。这个要 OpenAI 兼容 / Anthropic / Gemini / 本地模型，并发池里不能混 MyMemory 和 DeepL。默认关闭呃。
- 列表里的「状态」列措辞分得很清楚：英文 key 全被覆盖、硬编码也全翻完时，**AI 从零翻完的**显示「✓ 已 AI 汉化完成」，**人工打底、AI 只补缺口的**显示「✓ 已 AI 补完」，**全是人工汉化、摆渡压根没插手的**显示「◈ 人工·完整（已让位）」。鼠标悬停能看到人工和 AI 各占多少，同一个 key 优先算人工，不重复计。
- `en_us` 里没有文字的空 key 不算待翻译，也不计进比例。

要是扫到模组 JAR 的 `.class` 里有疑似写死的界面文字，状态列会标「⚠ 含硬编码·待翻N」—— N 是**还没翻完的条数**。翻完之后（译文记在本工具包旁的 `<资源包名>.hardcoded.json` 里）就不再挂 ⚠，会正常回到「已 AI 汉化完成 / 已 AI 补完」，免得明明干完了还挂个警告吓人。语言 key 全翻了不等于游戏里全中文，1.7.10 的 Inventory Pets 备注（`Favorite Food:` 那种）就是代码常量，Legends 也一大堆呃。具体哪条没翻，还是得对着游戏里的原句看，我也没有读心术哈哈。

## 右键菜单

列表里右键选中项：

- **删除本工具 AI 汉化**：把这个模组的 AI 译文从摆渡包里卸掉，回退到模组自带的人工和官方汉化，没有的话就显示英文。卸掉的译文存到 `<资源包名>.uninstalled.json`，列表标「AI 汉化已卸载」，不会被「继续翻译」偷偷加回来。
- **重载已卸载的 AI 汉化**：直接从记录恢复，不调模型。人工译文和「强制还原英文」的 key 不会被盖。
- **强制还原英文**：生成和更新覆盖包，把这个模组 `en_us` 里所有键用英文写进 `zh_cn`，连人工和官方汉化一起盖掉。包内用 `FERRY_REVERTED.json` 记录，重扫显示「已还原英文（不翻译）」，点「翻译全部待AI」也不会再翻回去。
- **重翻整个模组 / 联网安装人工汉化包 / 设置不翻译 key**。
- **加入不翻译名单**：这个模组完全跳过 AI 翻译，状态列显示「∅ 已排除（不翻译）」，「翻译全部待AI」和双击都会自动跳过它。右键选「移出不翻译名单」就恢复。做这个功能就是为了让你少手打几次 modid 呃。

删完会自动重扫。想撤销「强制还原英文」就把对应资源包删掉；卸载过的 AI 译文在右键里选「重载」。

## 联网功能

- **查询在线汉化**：表格里选中模组后点底部按钮，自动查 CFPA 社区整合包（内置来源）和你自己写的查询源，看哪些模组已有现成汉化，结果里可直接开链接。查询源在「设置 → 编辑查询源…」里加，每行一个网址，用 `{modid}` 代替模组 ID。
- **检查更新**：启动时每周自动查一次 GitHub 最新版本（弹窗里能关掉），「关于」页也能手动查。发现新版本可以直接自动更新，下载后替换 exe，重启生效，或者去发布页手动下载呃。
- **社区汉化基线**：拉 CFPA 的整合包，14 天缓存一次，本地抽取。更早那种按模组逐个访问 CDN 的方式因为 CFPA 半路改了目录结构，全员 404，这个 bug 在我眼皮底下活了两个版本才被发现哈哈，服了。
- **翻译硬编码文本**：设置摘要行勾选后，模组代码里疑似硬编码的英文会随翻译批一起交给 AI，译文存在资源包旁的 `.hardcoded.json`，走上面的桥接在游戏里替换显示。

## 版本兼容

1.6.1 之前没有资源包机制，所以不做，呃，1.6.1 是 2013 年的版本，能支持到这里我自己都没想到。所有汉化都靠资源包覆盖，不碰模组文件。

**1.6.1–1.12.2 旧版**：`pack_format` 1–2（1.6.1–1.10.2）写 `assets/<modid>/lang/zh_CN.lang`，`pack_format` 3（1.11–1.12.2）起资源包内文件名强制全小写、改写 `zh_cn.lang`，1.13+ 才写 `zh_cn.json`。这个大小写坑是我对着 wiki 查了半天才查到的，查完发现之前写的包在 1.12.2 上根本是哑弹，silently 无效那种，最恶心的 bug 类型呃。旧实例里如果已经有本工具生成的 JSON 包，重扫和翻译时会自动迁成 `.lang`，原 ZIP 先备份成同目录的 `.pre-lang-backup`。

**新版向上兼容**：优先读实例客户端 jar 里的 `version.json`，直接拿 `pack_version.resource_major/resource_minor`，比如 1.21.10→69.0，26.3→97.1，所以以后出新版本基本不用改代码。读不到才退回版本表，1.21.8→64，1.21.9→69.0，1.21.11→75.0，26.1→84.0，26.2→88.0，26.3→97.1，26.4→99.0，当前快照值，正式版以 version.json 为准。游戏现在是年份版本号（`26.2`、`26.3`），你要是填成 `1.26.3` 它会自动当成 `26.3`，会有人这么填的哈哈，我相信。1.21.9（25w31a）起 `pack.mcmeta` 用 `min_format` + `max_format`，整数或 `[major, minor]`，更早的还是 `pack_format`，读取时两种都认。

**版本表联网更新**：出新的 Minecraft 版本而本地版本表还没跟上时，工具会去仓库根目录的 `pack_formats.json` 拉最新表，raw.githubusercontent 主源加 jsDelivr 备源，结果缓存 24 小时到 `ferry_cache/`，拉不到就继续用内置表，再不行才弹手动选择。所以以后每次游戏更新，只要在 GitHub 上给这个 JSON 补一行，旧安装不用重新下载程序，这是我少数几个自己觉得机灵的设计呃。不想联网可以在 `ferry_config.json` 里把 `online_pack_format` 设成 `false`。

未知版本时 GUI 会让你手动选或者填，支持 97.1 这种小数，命令行用 `--pack-format N`，或者 `--yes` 硬按 15 走，包里会标「版本未确认」。HMCL 和 PCL 的私有配置我还没实机确认，`options.txt` 自动启用也一直关着，不是不想做，是怕做错。

> 资源包能被游戏加载 ≠ 模组文字真的变了，这个还是得进游戏看启用和关闭前后的物品名。说的就是我，写完全部代码才第一次进游戏验证呃。

## 术语表

翻译时会把 Mojang 自动词库当上下文术语提示，比如 `Redstone Dust` → 红石粉，不再把 `Lead`、`Map` 这类多义短词脱离句子强行替换，之前的做法确实蠢哈哈，被测试逮到才改的呃。你在 `ferry_config.json` 的 `glossary` 里亲自填的词仍会严格固定，模组名和 Forge/NeoForge 等品牌词也会保护。

联网更新官方术语表，从 Mojang 官方语言文件里提取实体、附魔、效果、物品名：

```powershell
py mc_ai_translator.py glossary --update   # 联网下载并提取
py mc_ai_translator.py glossary            # 看概况
py mc_ai_translator.py glossary --show     # 列全部条目
```

结果存在 `user_glossary.json`，可以手动改；`ferry_config.json` 里的 `glossary` 和 `keep_untranslated` 也能加自定义术语和不翻译的词。

## 并发与多模型加速

默认串行，`concurrency` 控制同时翻几个批次：

```powershell
py mc_ai_translator.py translate --instance "..." --concurrency 3
```

多模型池在 `ferry_config.json` 里配 `model_pool`，按批次轮换给不同引擎，配合 `concurrency` 并行提速：

```json
{
  "model_pool": [
    { "engine": "mymemory", "weight": 3 },
    { "engine": "openai", "api_key": "sk-...", "model": "gpt-4o-mini", "weight": 1 },
    { "engine": "local", "base_url": "http://127.0.0.1:11434/v1", "model": "qwen2.5", "weight": 2 }
  ]
}
```

批次按「字符量 ÷ weight」贪心分，贵的、量大的少分，免费便宜的给高 `weight` 多分，尽量让各模型花的钱差不多呃。翻完会报告每个模型用了多少条、多少批、多少字。GUI「设置」里能图形化加模型，从预设一键拉进池子。

> MyMemory 免费额度有限，并发别太高，2~4 差不多；付费和本地引擎可以往高调。

## 配置与密钥

参数从 `ferry_config.json` 读，key、base URL、模型、引擎、pack_format、各种开关都在里面。没有这个文件就用内置默认值。

```powershell
py mc_ai_translator.py config          # 看当前配置（Key 已打码）
py mc_ai_translator.py config --init   # 生成默认配置
```

**API Key 会加密后再落盘**：Windows 上用系统自带的 DPAPI，存成 `dpapi:<密文>`，
用的是当前**用户账户**的凭据 —— 换一台机器、换一个 Windows 账户都解不开，所以这个文件
被别人拿到、或者被网盘同步走也没关系。读的时候自动解密，你无感。内存里仍是明文
（不然没法拿去调接口），要防的是**文件泄漏**，不是防同机抓内存。非 Windows 平台没有
DPAPI，会退化成明文存（会写进日志提醒），因为摆渡本来就是 Windows 桌面工具呃。

**老配置会自动迁移**：如果你是从早期版本升上来的（那时 Key 是明文存的），不用手动做什么
——程序**下一次启动**读到明文 Key 就会自动加密写回磁盘。迁移前会先做一次「加密→解密→
逐字比对」自检，确认密文解得回来才落盘；任何一步不放心就干脆不动你的文件。

## 保护规则（写代码时就守着的）

- AI 只翻人工汉化没覆盖的 `en_us` key；主动开语料补缺时，人工译文只当参考，绝不覆盖呃。
- 汉化组后续补上的译文，摆渡会自动撤回自己生成的那几条并播报，不是失败，是让位。
- 不内置第三方汉化词典。
- 资源包不改原模组 JAR，删了就还原。
- 占位符（`%s` `%d` `%1$s` `{0}` `§a` `$(br)` 等）校验失败就保留英文。
- 翻译随时能停，产出是个只含已翻部分但能直接用的不完整包；单批失败自动重试并跳过，已完成的批次进缓存，下次接着来呃。

这几条是红线，不是为了好看写的。每次让 AI 改代码我都把这几条贴在提示词最前面，贴了八百遍呃。

## 开发 / 测试

- Python 3.11+，只用标准库，`tomllib`、tkinter 这些，没有第三方依赖呃，不是清高，是不会用包管理器哈哈。
- 跑测试：

```powershell
python -m unittest -v test_spec_p0 test_refine
```

- CI 在 `.github/workflows/tests.yml`，push 和 PR 时在 Python 3.11、3.12 上跑上面这些测试。目前 99 个全绿，绿的每一行都是修过之后才绿的呃。
- 桥接模组在 `bridge/`，1.20.1 Forge，`.github/workflows/bridge.yml` 会构建它；自研桥已解冻并在跑，和 LiteralBridge 供数路线并行（前者管 tooltip / 聊天，后者管 NBT 显示层）。
- 本地构建桥（改完 Java 想自己出 jar）：`cd bridge && ./build.sh`。离线优先，缓存缺件会自动联网补一次；新机器先跑 `bash tools/prefetch-forge-deps.sh` 生成 `.forge-prefetch/m2`。产物是 `bridge/build/libs/ferrybridge-1.0.0.jar`。
- **代码结构**见 `docs/ARCHITECTURE.md`：`mc_ai_translator.py` 是 57 行的薄壳（重新导出 `ferrycore` 的名字 + 转交 CLI），实现在 `ferrycore/` 的 18 个模块里，依赖单向分层。动代码前先读那份文档 —— 尤其「`mock.patch.object(core, "X")` 跨模块会静默失效」那一节，那是拆分时最容易踩的坑。
- 设计文档在 `docs/`：`ARCHITECTURE.md` 是代码结构与拆分路线，`PLAN_SCALE_UP.md` 是规模化路线（大批量翻译 / 去 Mixin / 多加载器 / 多版本），`TEST_DESKTOP_ONESTEP.md` 是桌面「一步到位」流程的测试清单，`TEST_COLLECT_ROUND1.md` 是游戏内采集（开发者补漏）的测试清单。
- 自己打包 exe（**平时用不着** —— 打 tag 时 CI 会自动构建并发到 Release）：

```powershell
py -m PyInstaller --onefile --windowed --name ProjectFerry --icon ferry_icon.ico --add-data "ferry_icon.png;." ProjectFerry.pyw
```
