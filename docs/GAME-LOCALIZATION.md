# 通用游戏汉化手册

[返回项目首页](../README.md) · [下载工作台](https://redrea1ity.github.io/ProjectFerry/#downloads)

拿到一份没有中文的游戏，第一步不是选模型，而是看摆渡能读出多少文字、能不能把译文放回去。两项结论可能不同。请在游戏副本上操作；磁盘镜像、安装包和存档也应另行备份。

## 第一次：先让游戏说一句中文

1. 打开左侧「游戏汉化」，选择游戏目录、镜像或程序，点「检测游戏」。看报告里的识别结果、可提取条数和写回条件。如果没有文本，不要启动翻译。
2. 点「① 提取文本(自翻)」。保留生成的 `ferry_tl.json` 工程表，打开同目录的 `ferry_tl.tsv` 双语表。在 `dst` 列试译一条容易找到的菜单文字；保留占位符、换行标记和控制符。
3. 保存表格。用「导入外部译文…」选中刚编辑的 TSV，再确认重打包；如果直接改的是 JSON 工程表，保存后点「② 自翻回录重打包」。提取、手工校对和写回都不用翻译接口。
4. 打开报告列出的产物，用对应的游戏或模拟器回到那条菜单，检查中文、字形、换行和按键提示。第一条跑通了，再处理整段剧本。要回退可用「撤销汉化」；不要只依赖撤销记录代替原档。

有现成译稿就直接回录，不必让模型重译。需要机器初稿时，在「翻译引擎」配置服务，再回游戏汉化页开始；长句、专有名词和选项建议人工复核。有些旧格式限制的是**编码后的字节数**而非字数，超长应缩写，缺字应先检查字体。

## 哪些格式值得先试

下表是 2.0.0-alpha.5 已注册的适配器，不是实机兼容清单。同一引擎不同版本或不同作品，使用的封装、字库和脚本都可能不同。

| 你手里的游戏 | 适配器标识 | 优先检查的内容 |
| --- | --- | --- |
| 日系视觉小说、同人 RPG | `kirikiri`、`renpy`、`tyrano`、`onscripter`、`artemis`、`wolfrpg`、`rpgmaker_2k`、`rpgmaker_ace`、`rpgmaker` | 对话、人物名、菜单；对照原作检查控制符。 |
| PC 与独立游戏 | `godot`、`unity`、`unreal`、`gamemaker`、`love2d`、`narrative`、`i18n_table` | 场景文本、叙事脚本和现成语言表，例如 Godot 场景、Ink、Yarn、Gettext。 |
| 复古电脑、旧 Windows 与 Flash | `pc98`、`retro_win`、`flash`、`hsp`、`rawbin` | 老编码、字库与定长文本；报告不建议写回时先停在提取阶段。 |
| 手机与功能机 | `apk`、`ipa`、`j2me`、`symbian`、`blackberry` | 包内词表或脚本；塞班、黑莓是本版实验项，生成文件不等于能安装运行。 |
| 掌机 | `psp`、`psv`、`nds` | 镜像内可读的脚本或资源；输出位置和形式以报告为准。 |

## 从源码做只读检查

在项目根目录执行。历史脚本名虽然带有 `mc`，`localize` 子命令处理的却是通用游戏：

```powershell
py -3 mc_ai_translator.py localize --list-adapters
py -3 mc_ai_translator.py localize "D:\Games\游戏副本" --dry-run
```

在 alpha.5 源码上，独立入口 `python -m ferrygame` 可在启动阶段因 PC-98 适配器循环导入而报错。上面的入口可以列出格式并做只读检测；需要提取双语表、回录或校对时请用桌面工作台。
