# 大批量采集链路 · 第一轮实机测试清单

> 2026-10-12。本轮要验证的只有一件事：**桥能不能把没翻到的英文采下来 → 摆渡能不能翻好写回去 → 游戏能不能不重启就生效。**
> 三个环节任一断了，下面的「判读」会告诉你断在哪一环。

---

## 前置检查

- 桥 jar 已部署：`D:\Minecraft\versions\1.20.1-单独仙境吃屎版\mods\ferrybridge-1.0.0.jar`（37888 B，10-12 09:11）
- **用 `ProjectFerry.bat` 启动摆渡，不要用 `ProjectFerry.exe`** —— exe 是旧的打包版，没有本轮新增的按钮
- 游戏目录的 `ferrybridge.json` 保持 `{"enabled": true}`（当前就是这个值）

游戏目录 = `D:\Minecraft\versions\1.20.1-单独仙境吃屎版\`

---

## 第一步：让桥采集（进游戏）

1. 启动游戏，进存档。
2. 按 **F9** 打开摆渡桥浮层。应该能看到这些行：

   ```
   摆渡桥 FerryBridge（实时状态，F9 关闭）
   映射表  58 条
   注入开关 开启（正常替换）
   生效注入点 N 个（去重）
   已替换  0 次
   未命中  ...
   已采集  0 条 (批量翻译原料)      ← 本轮新增的这一行
   ```

3. **悬停几个物品**。优先选没汉化的恐怖模组：雾中人 (`The-Man-From-The-Fog`)、
   `the_knocker`、`the_obsessed`、`super_scary`。
4. 在**聊天栏打一句话**（随便发，比如 `test`）。
5. 回到浮层看「**已采集**」那个数字。

**判读**
- 数字开始涨 → 采集器通了，进第二步。
- 一直是 0 → 采集器没接上。先看游戏目录有没有 `ferrybridge-collected.txt`，
  然后把情况告诉我，我来查。

---

## 第二步：翻译并写回（回桌面）

1. 退出游戏（或者就切到桌面，采集文件是实时写的）。
2. 双击 `ProjectFerry.bat` 打开摆渡。
3. 确认下拉框选的是 `D:\Minecraft\versions\1.20.1-单独仙境吃屎版`。
4. 点底部的「**导入游戏采集**」。
5. 它会先弹窗告诉你采集到多少条（按「聊天栏 / 物品 tooltip」分开列），点「是」开始翻译。
6. 翻译完会再弹一次窗。

**判读**
- 弹出「没有采集数据」→ 第一步没成，回去看。
- 弹出「已写出 N 条摆渡桥映射：<路径>」→ 成了，进第三步。
- 报错 → 把弹窗原文发我。最常见的原因是翻译引擎没配好（当前配置是 `openai`，需要 API key；
  临时想试通链路的话，可以在设置里换 `mymemory` 免费引擎）。

---

## 第三步：验证热重载（这一步才是关键）

**重点是：不要重启游戏。**

1. 游戏还开着的话就直接回到游戏；刚关了就重新进一次。
2. 再去悬停刚才那些物品、看聊天栏。
3. 按 F9 看浮层的「**已替换**」数字。

**判读**

| 现象 | 说明 |
|---|---|
| 「已替换」涨了、tooltip 变中文 | ✅ 整条链路通了 |
| 「映射表条数」涨了但「已替换」还是 0 | 表加载了、但文本没对上（可能带格式码或换行差异） |
| 「映射表条数」完全没变 | 热重载没生效（文件路径或 mtime 比对的问题） |

---

## 三个文件分别在哪

| 文件 | 位置 | 作用 |
|---|---|---|
| `ferrybridge-collected.txt` | 游戏目录 | 桥采集的待翻译清单（人可读，可以自己打开看） |
| `ferrybridge-mappings.json` | 游戏目录 | 摆渡写出的映射表；**桥读的是这一份** |
| `ferrybridge-status.txt` | 游戏目录 | 实时状态（F9 浮层内容的文字版，随时可查） |

---

## 一个容易误判的点

悬停**仙境模组**的物品，看到的本来就是中文 —— 因为仙境自带汉化包
（`mods/wonderland_zhcn-1.0.0.jar`，Losketch 翻译），与摆渡桥无关。
**要看桥的效果，请用没汉化的那些恐怖模组。**
