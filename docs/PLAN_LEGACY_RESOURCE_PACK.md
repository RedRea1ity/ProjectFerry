# 早期 Minecraft 模组汉化资源包覆盖验证计划

状态：**已暂停（用户要求先做向上兼容，向下兼容留待下一个小版本）**。已完成部分：1.7.10 Forge 实例复现“认包但无汉化”，`pack_format` 1–3 的摆渡输出改为 `zh_CN.lang` 并迁移了该实例原有 ZIP（保留 `.pre-lang-backup`）。游戏内是否生效未复测；未修改 `options.txt`。

后续实测反馈“汉化不完全”：静态核对显示该实例的 7 个语言命名空间共 2375 条摆渡译文，所有有效英文 lang key 均被人工或摆渡包覆盖。Inventory Pets 中 `Favorite Food:` 等备注写在几十个 `pet*.class` 内，并非语言 key，资源包无法覆盖。Legends 的 `itemGroup.suitsAlt` 在包中有“替换角色套装”译文，但大量其他 UI 文本也存在 `.class` 中；需记录游戏里实际未汉化的原句，逐条归因。列表对这些模组不再标示“已完全汉化”。

## 目标与边界

找出本项目可以用**玩家资源包**覆盖模组 `zh_cn` 的最早 Minecraft/加载器组合。分别证明两件事：游戏接受资源包，以及资源包里的译文实际显示在模组界面/物品名里。仅看 ZIP 内容或菜单显示为已启用，不算覆盖成功。

- 不修改模组 JAR、现有人工汉化包或玩家存档；测试资源包只放在独立测试实例。
- 只使用容易识别、原模组中确实存在的一个 lang key；测试译文用明显但无特殊格式的中文，保留原文占位符。
- 对已有人工汉化只做对照测试，不覆盖它；自动启用 `options.txt` 保持关闭。测试后移除测试包即可恢复。

## 阶段 1：查证版本与准备样本

1. 查证资源包机制首次出现的具体 Java 版，并核对该版和目标加载器（优先 Forge）的 `pack.mcmeta`、资源路径、语言文件扩展名及语言代码大小写要求。不要仅凭当前 `PACK_FORMATS` 表推断“最早版本”。
2. 准备互相独立的测试实例：最早有资源包机制的可运行版、1.6.4、1.7.10、1.12.2、1.13+。每个实例记录游戏版本、Forge/其他加载器版本、Java 版本和系统环境；若最早版本与 1.6.4 相同，可合并。
3. 每个实例选择一个带玩家可见文本的模组，确认 JAR 中 `en_us`、`zh_cn` 的真实路径、格式和待测 key。缺少原模组中文时，记录英文 fallback；已有中文时，用只读基线记录原显示值。备份测试实例的 `options.txt` 与资源包列表，记录原文件哈希。

## 阶段 2：最小资源包实机实验（不走 AI）

1. 为每个版本手工做只包含 `pack.mcmeta` 和一个测试 key 的最小包，按该版本实际要求选用 `.lang` 或 `.json`；不复用其他版本的格式文件。
2. 游戏关闭时把包放入**测试实例**的 `resourcepacks`，在游戏 UI 手动启用。先确认游戏是否列出/接受该包，并记录任何版本不兼容提示与日志。
3. 进入能看到测试模组物品/界面的场景，按“未启用 → 已启用 → 再关闭”比较实际文字；保存截图、游戏日志、包哈希及 `options.txt` 变化。只有文字跟随开关恢复，才判定为覆盖成功。
4. 用含两个 key 的对照包测试按 key 补缺：只覆盖一个 key 时另一个应保留模组/人工原译文；若整份语言文件被替换导致另一 key 丢失，立即暂停“只补缺失 key”自动生成，并记录该版本需整文件输出或无法安全支持。
5. 再用独立的人工汉化包做优先级对照：验证摆渡包处于较低优先级时人工译文能接管；实际游戏 UI 的上下顺序与 `options.txt` 数组顺序只在此步骤核对，不能预设。

## 阶段 3：差异归因与实现门槛

按每个版本填写矩阵：游戏/加载器、`pack_format`、语言扩展名与路径、游戏是否认包、模组文本是否被覆盖、按 key 是否合并、人工包是否优先、日志/截图、结论。

- 游戏不认包：先检查该版本 `pack.mcmeta` 和版本目录识别，不能当成“模组资源不可覆盖”。
- 认包但模组文字不变：检查 namespace、语言代码大小写、加载器资源优先级，以及目标文本是否真由 lang key 提供。
- 不支持安全的按 key 合并或不能让位人工译文：该版本不自动输出汉化包，展示“不支持/待验证”及理由。
- 已由 1.7.10 实例的实际资源包与模组 JAR 证实语言扩展名不匹配，因此先修复旧版 `.lang` 输出；仍需进游戏验证实际覆盖及 R1 人工优先。仅在验证 `options.txt` 顺序及“游戏未运行”后，另行考虑自动启用。

## 验收

- 最早可用版本有完整证据链：两个开关状态的游戏截图、日志、最小包及环境版本记录。
- `.lang`、`pack.mcmeta`、namespace、按 key 合并和人工优先均有独立结论；无证据的版本不宣称支持。
- 隔离测试实例可通过移除包恢复，原模组/人工包哈希不变；任何实现前后都运行现有单元测试与当前 1.20.1 实例扫描回归。
