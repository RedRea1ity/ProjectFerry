# 桌面「一步到位」流程 · 测试清单

> 2026-10-12 第二轮。本轮把主流程从「进游戏采集 → 回桌面翻译 → 写回」
> 改成 **「进游戏之前全在摆渡里做完」**；游戏内采集降级成开发者补漏。

---

## 一、本轮到底改了什么（人话版）

| 之前 | 现在 |
|---|---|
| 翻译完还要**手动点一次**「导出桥接映射」，游戏里才有中文 | 译完**自动**把映射写进游戏目录（设置行勾了「译完自动导出桥映射」，默认开） |
| 扫描 / 翻译 / 导出 三个动作，三步走 | 勾「翻译硬编码文本」→ 开始翻译 → 完事，**一步到位** |
| 「导入游戏采集」看起来像主流程 | 改名「**导入游戏采集（开发者补漏）**」，明确只给开发者用 |
| 桥按「原样字符串」查表 | 加了**格式噪声归一化**：剥 `§` 颜色码 + 把排版省略号 `…` 折成 `...` |
| 状态列只有一句笼统的「完成」 | 拆成「**已 AI 汉化完成 / 已 AI 补完 / 人工·完整（已让位）**」，硬编码翻完就不挂 ⚠ |
| 下载失败会闷头重试 5 次、最多干等 105 秒 | 只轻量重试一次，**失败直接打开项目页**（不刷成功率，也不加第三方镜像） |

「格式噪声归一化」不是花活：**同一句话，写死在 class 里的形态和游戏里显示出来的形态
不总是逐字符相同** —— 前者可能是 `...`，后者是 `……`；前者不带 `§` 码，后者带。
不抹平这个差异，就会出现「明明扫出来翻了，游戏里还是原文」。

## 二、主流程测试（不用进游戏）

游戏目录 = `D:\Minecraft\versions\1.20.1-单独仙境吃屎版\`
**用 `ProjectFerry.bat` 启动摆渡，不要用 `ProjectFerry.exe`**（exe 是旧打包版，没有新按钮）。

1. 打开摆渡，下拉框确认是上面那个实例。
2. 点「**扫描**」，等表格列出来。
3. 确认设置摘要行里两个勾都开着：
   「**翻译硬编码文本**」+「**译完自动导出桥映射**」。

**判读**
- 看到「已自动导出桥接映射 M 条」→ 桌面流程走通了，直接进游戏看效果。
- 没看到 → 说明自动导出没触发（可能勾没开、或这次没有任何要翻的东西）。

## 三、进游戏验收

1. 进游戏（**不用重启**；游戏本来就关着就直接开）。
2. 按 **F9** 看摆渡桥浮层：映射表条数应该 ≥ 桌面导出的 M 条。
3. 悬停 `boh` 的物品、按 Shift 看扩展 tooltip；触发 The God 的右键生命卷轴聊天文本。
4. 看「**已替换**」数字有没有涨。

**判读**

| 现象 | 说明 |
|---|---|
| 文本变中文、「已替换」涨 | ✅ 通了 |
| 映射表条数涨了、但文本还是英文 | 运行时长句和字典里的写法仍有差异 —— 把这句原文发我，我加归一化规则 |
| 映射表条数完全没变 | 自动导出没写成，或游戏读的不是这份文件 |

## 四、The God「某些聊天文本没汉化」——已逐条查清

The God 一共 **32 句**玩家可见文本，**29 句已在映射表**，只有 3 句缺：

| 缺失 | 所在类 | 为什么 |
|---|---|---|
| `God is here` | `GodPriObnovlieniiTikaSushchnostiProcedure` | 译文批次漏了一条，**重翻该模组**即可补上 |
| `Failed to create folder.` | `TextfileProcedure` | 以 `Failed` 开头，被启发式**当作日志剔除** |
| `Error writing file: ` | `TextfileProcedure` | 以 `Error` 开头，同上 |

**放宽启发式不划算**（实测过）：会多放进 **200+ 条**真正是日志的句子（JEI 文档、
Xaero 的 IO 异常、mixin 报错…），为 2 条报错文本灌这么多噪声不值得。
所以这 2 条**故意不修**，需要时可以手动加进映射表。

另外查清一件事：游戏里**同时**跑着两个汉化引擎 —— LiteralBridge（按**子串**替换）
和自研桥（按**整条**精确匹配），The God 那句长文本两边都有规则。这是「半中半英」
这类怪现象的潜在来源，分工后面要理清。

## 八、LiteralBridge 自动下载 / 自动升级（2026-10-12 新增，可选）

原来「mods 里没有 LiteralBridge → 直接打开项目页」，现在改成
**网络通就自己下**：从 GitHub Release 挑匹配你「加载器 + 游戏版本」的那个 jar，
丢进实例 `mods/`；**只有网络不通、或没有支持你这版的本体时**，才打开项目页。

2026-10-12 又加了**自动升级**（设置行勾选「自动升级 LiteralBridge」，默认开）：
已经装了 LiteralBridge 的实例，在导出桥映射时会顺带查一次有没有新版。

### 自动升级的三条硬保证

1. **已经是最新时只查不下载** —— 只打一次 GitHub API，不浪费流量、也不会因为下载失败误报错。
2. **绝不留两份同 modId 的 jar** —— 换新版前先把旧版改名成 `xxx.jar.bak-<时间>`（**只改名，不删除**，
   想回退把文件名里的 `.bak-…` 去掉就行）。同一个 modId 的两份 jar 同时存在会**直接崩游戏**，
   所以这一步是硬的。
3. **旧版改名失败就放弃升级** —— 宁可没升，也不能留下一份会崩游戏的目录。

### 怎么验证

**你现在的两个 1.20.1 实例里都已经装了 `literalbridge-forge-1.20.1-1.2.0.jar`。**

**A. 看自动升级（最省事，直接就能看到）**
1. 摆渡里选 `1.20.1-单独仙境吃屎版` 或 `1.20.1-Forge_47.4.22`。
2. 点「导出桥接映射」（不用先翻译）。
3. 状态栏/弹窗应报「LiteralBridge 已从 1.2.0 升级到 1.3.0，重启游戏后生效」，
   `mods\` 里出现 `literalbridge-1.3.0.jar`，同时旧版变成
   `literalbridge-forge-1.20.1-1.2.0.jar.bak-<时间戳>`。
4. **再点一次**「导出桥接映射」→ 应报「LiteralBridge 已是最新（1.3.0），无需更新」，
   且 `mods\` 目录**一个文件都没动**。这一步验证的是「已经最新时只查不下载」。

> ⚠️ 这一步会**真的动你的 `mods\` 目录**（旧版改名 + 新版落盘）。
> 不想动的话先做 B / C。

**B. 看「下不动就开网页」这条（不碰你的文件）**
1. 摆渡里切到 `1.21.10-NeoForge_21.10.64` 实例。
2. 随便挑个模组翻译一点，然后点「导出桥接映射」。
3. 应该弹窗说「没有支持 NeoForge + Minecraft 1.21.10 的 LiteralBridge」，并打开项目页。
   —— 这是**正确行为**：它只有 Forge 版、MC 范围 `[1.20.1,1.21)`，不会硬塞一个装不上的 jar。

**C. 看「真的下载下来」这条（在临时目录里做，不碰游戏）**
在项目目录下跑（会复制你的 LiteralBridge 到临时目录再升级，游戏目录不动）：

```bash
"C:/Users/zetad/.workbuddy/binaries/python/versions/3.13.12/python.exe" - <<'PY'
```

### 已知边界
- LiteralBridge 是**模组**，装进 `mods/` 后**必须重启游戏**才加载（摆渡桥的映射表能热重载，模组不行）。
- **GitHub 附件在国内网络下实测约一半的尝试会失败**（连接无人应答，固定卡 21 秒才报错）。
  **不去刷成功率** —— 只轻量重试一次，失败就直接打开项目页让你自己下（那条路永远可用）。
  反正在后台线程，不卡界面。看到「联网获取 LiteralBridge 失败」不影响已装的旧版继续用。
  也不打算加第三方 GitHub 代理镜像（那等于塞个能换包的中间人进来）。
- NeoForge / MC 1.21+ 的硬编码汉化，只能靠**自研摆渡桥**兜 —— 这条是既定路线，
  见 `docs/PLAN_SCALE_UP.md` 的 L1→L2→L3。

## 九、状态列新措辞（2026-10-12 新增）

列表「状态」列不再是一句笼统的「完成」，改成**分清功过**：

| 状态列显示 | 含义 |
|---|---|
| ✓ 已 AI 汉化完成 | 英文 key 全是 AI 翻的（没有人工打底），硬编码也翻完了 |
| ✓ 已 AI 补完 | 有人工汉化打底，AI 只把缺口补上 |
| ◈ 人工·完整（已让位） | 全是人工/官方汉化，摆渡压根没插手 |
| ⚠ 含硬编码·待翻N | 语言文件通了，但走桥的硬编码还剩 N 条没翻 |
| ⚠ 含硬编码·待翻N·缺M | 上面那条 + 语言文件也还缺 M 个 key |

**为什么这么改**：摆渡的定位是「临时的、到岸即离」，人工干的活不能算成 AI 的功劳 ——
这就是「全世界最尊重汉化组的临时 AI 汉化工具」那句话落到实处的地方。

### 怎么验证

1. 选 `1.20.1-单独仙境吃屎版`，点「扫描」。
2. **挑一个只被 AI 翻过的模组** → 状态列应是「✓ 已 AI 汉化完成」。
   悬停能看到人工/AI 各占多少。
3. **挑一个检出硬编码、但还没跑过「翻译硬编码文本」的模组** → 状态列应是
   「⚠ 含硬编码·待翻N」，N 是待翻条数。
4. 勾上「翻译硬编码文本」→ 开始翻译 → 译完自动导出桥接映射 → **再点「扫描」**。
   同一个模组的状态应**摘掉 ⚠**，回到「✓ 已 AI 汉化完成 / ✓ 已 AI 补完」。
   —— 这一步就是你说的「硬编码都汉化完成了，状态该显示已完成」。
5. 筛选器选「只看已完成」，上面那个模组应该出现在结果里（以前会被 ⚠ 挡在外面）。

> 「待翻N」是拿工具自己记的 `<资源包名>.hardcoded.json` 跟检测出来的硬编码原文比出来的
> —— 比的是**条数**，不是猜的。所以只要那个文件在，状态就是准的。
